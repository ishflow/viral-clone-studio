# Assemble attempt directory isolation

Ruling: design handover rather than a render-core refactor in this brief. `produce/assemble.test.ts` has 93 expanded cases before the new characterization and 94 now, not approximately 12; many pin the shared variant directory's `edit.json`, `timeline.json`, assets and normalised clips. The existing output-name/owner checks stop a late final-video publication, but intermediate composition files remain shared. No change to the C1d-owned compose/renderer/encode core is included here.

The proposed boundary is `jobs/<run>/v<n>/attempts/<random UUID>/`. Every normalised clip, linked asset, edit document, composition, timeline, quality report, rendered video and poster lives in that directory until completion. Use a UUID per invocation rather than the sanitised worker name: two invocations of one worker and names with the same sanitised form must not collide. Paid operation outputs stay immutable at their existing paths; an attempt may reference them but never replace them.

Publication takes `BEGIN IMMEDIATE`, checks `holds(db, run.id, run.claimedBy)`, and records a pointer to the complete, immutable attempt in the variant result. Return video/poster paths inside that attempt, and make inspect read the same attempt's edit/timeline/quality files. Readers resolve the attempt once per request; they must not combine files from two generations. Do not copy several files into shared public paths: SQLite cannot roll back filesystem copies, and a crash or a reader outside the transaction can see a mixed set. Compatibility for callers expecting the variant root must be implemented by resolving the recorded attempt, not by recreating shared mutable intermediate files. The result pointer and the owner-scoped result record must commit together; this needs changes in produce's result persistence as well as assemble. Only the owner can publish the pointer. An obsolete attempt returns the existing `engine-error` outcome and touches no other attempt or published file. Interrupted/unreferenced attempts remain unserved and can be retired by a later retention task; physical deletion policy is separate.

Required regressions: (1) takeover during clip normalisation, (2) takeover while renderer holds composition input files, (3) old worker returning after a new worker published, (4) two worker names that sanitise identically, (5) SIGTERM/crash and retry using the original paid operations, (6) publication transaction blocks takeover until the whole public set is consistent. Update the assembly test declarations and all 94 expanded cases to inspect the attempt path and the published path separately; run the existing real produce/robustness suites and compare their timelines and output checks. Do not retain shared intermediate filenames just to keep old tests passing.

## Round 2 measured reproduction

`assemble.test.ts`, case `characterizes the open shared-clip race`, deterministically suspends the first worker's decoder output until a replacement worker completes the entire variant. It then lets the obsolete decoder write its output. The obsolete assemble returns `engine-error`, and the new owner's final video and quality record stay intact, but `assets/clip-s1.mp4` now reads the obsolete bytes through its shared normalised-clip link. This is a characterization test asserting the current defect, not a safety regression or a production fix. After isolation is implemented, replace its contamination assertions with preservation assertions and test overlapping renderer reads too.

Severity: medium reliability/custody defect within one run; no cross-owner access is demonstrated. During an overlapping render, contaminated input can affect the replacement render itself, whereas the final-publication ownership check only protects against an obsolete final rename. Owner checks before an awaited decoder are insufficient because an already-running tool can write after ownership changes. Killing an old tool alone is insufficient without fencing its output path.

The first release boundary should therefore include UUID work directories, immutable paid source references, result-pointer publication, inspect/media reader integration and all six race/crash regressions together. Do not ship only a UUID suffix on the final render name and label intermediate custody fixed.
